AI Safety.

The course, verified — every chapter, project, dataset, and claim on this page traced to a source someone actually read.

This repository is an advanced, dependency-aware learning roadmap for experienced ML engineers, security engineers, and aspiring technical AI-safety researchers; a coherent 24-chapter course with original explanations, worked examples, critique, and assessments; a research notebook of paper notes with real methodological analysis; ten runnable projects that work offline on a laptop; an annotated resource index; and a maintained open-source project you can navigate, run, cite, and contribute to. Free to read, free to run at meaningful small scale — no paid API or subscription on the core path. What it does not pretend to be: a substitute for the compute-tier experiments it honestly marks as not executed (the honesty ledger keeps that list at the front door).

The organizing chain used throughout risk or failure hypothesis→assumptions and threat model→observable evidence→intervention→evaluation→limitations→revised claim

Every number above is generated — this page is rebuilt from the repository's own registers, catalogs, and test suite by scripts/build_dashboard.py. Nothing is hand-maintained; when the corpus grows, the page changes with it or the build fails.

§ 01 · Verification

How every claim was verified

the evidence ladder · five access levels · one non-negotiable habit

The course's spine is not a topic list — it is a verification discipline. Every external fact in this repository lives in the source register with an access level recording how far into the source this build actually read, and a retrieval date. A retrieval date is not a publication date; an abstract-level read is not a full-text read; a page-inspection is not a read at all. The ladder below is the whole corpus, counted honestly at each level.

The judge's instrument

The judge of this curriculum is you, holding one question: show me the evidence. The register is built so that question never stalls — every entry can be audited in under a minute: click the source ID, see what was fetched, when, and how far into it the course actually read. Claims carry counterevidence slots and strength grades in the claims register, so a strong claim and a plausible one never wear the same badge.

The learner's version of the habit — where each kind of information actually lives, what an access level is, how to write a falsifiable claim, and a five-minute drill you can run right now — is the short field guide at prerequisites/verifying-sources.md. The whole course runs on it; this ladder is what it looks like at scale.

Red flags the register is built to catch: a number with no denominator · a benchmark quoted as a construct it does not measure · "peer-reviewed" attached to a preprint · a vendor's self-evaluation labeled an independent audit · a link that was never fetched. The re-check rotation re-fetches a sample of register URLs on a schedule recorded in MAINTENANCE.md — two rotations so far, one genuinely dead link caught and corrected.

§ 02 · What was not run

The honesty ledger

the not-executed tiers — shown at the front door, not buried

A curriculum that sells verification discipline must display its own gaps. The tiers below are the experiments this build did not execute — compute was out of scope for an offline, CPU-only, no-API-keys repository, and each project's README carries its protocol written out for whoever runs it. Hiding these would betray the method this page is selling; every number in the ledger above is green because these stayed red.

The standing rule, binding on contributions: project statuses (protocol-only, implemented, smoke-tested, experiment-executed) match reality on disk; independently-reproduced requires real external reproduction evidence. 0 of 3 required course-wide compute-tier executions are done — recorded honestly in planning/STATUS.md.

§ 04 · The build

§ 05 · The research notebook

Paper notes & comparisons

methodological analyses, not summaries — each anchored to a register source, each ending in a falsifiable extension

Paper notes are written at the level the register's access supports — method-level analysis for full-text reads, abstract-level entries say so — and every note ends in a falsifiable extension runnable at the course's deterministic tier: a claim you could imagine being wrong, with the observation that would weaken it. Comparison notes settle practitioner decisions single papers leave open. The fastest way in is through the chapter you are already reading: chapters name their note companions in their readings sections.

§ 06 · The incident record

Incidents, four eras

production failures reviewed under the strict template — facts first, unknowns kept unknown

Every incident below was reviewed with the strict template: observable facts first, established conclusions attributed, unknowns kept unknown, and every what this does NOT demonstrate written down. First-party reports outrank press coverage; where only press coverage exists, the note says so. Each feeds the same control family — enforceable output boundaries plus release-gated evaluation — and the accountability era adds the third leg: audit the training data and the deployed behavior before the regulator or the press does it for you.
