# Interviews — the preparation layer

**Navigate:** [← the learner's map](../START_HERE.md) ·
[careers index](../roadmaps/careers-index.md) ·
[the market](market/README.md) · [the roles](roles/README.md) ·
[the questions](questions/README.md) · [the take-homes](takehomes/README.md)

**What this layer is.** The missing piece the corpus had: a
preparation path from "I can run the projects" to "I can pass the
loop." It covers the market signal, the role families, the question
banks with worked answers, the take-home format, and the system-design
round — each grounded in registered, real-world data.

**What this layer is not.** A promise of outcomes. Every market number
is a dated snapshot with its access level stated; every figure traces
to a register entry you can audit
([source register](../research/source-register.yaml) ·
[claims register](../research/claims-register.yaml)), and the honest
version of interview prep re-checks the primary sources before
relying on any of them.

**Method acknowledgment.** The layer's structure — market, roles,
question banks, take-homes, system design — takes inspiration from the
[AI Engineering Field Guide](https://github.com/alexeygrigorev/ai-engineering-field-guide)
(registered as SRC-REPORT-051). That repository's basis (6,964
job-description analyses) is its author's own claim, carried here with
that label as inspiration provenance — never as evidence for any
figure in this repository. Every number below comes from this
repository's own registered sources instead.

**How to use it, in order:**

1. Read the [market](market/README.md) pages first — the demand
   signal, the skills outlook, the compensation notes, and the
   employment outlook. Knowing the shape of the market tells you which
   role to prepare for.
2. Pick your role in [roles](roles/README.md) — one of five families,
   each mapped to the course routes and capstones already in this
   repository.
3. Work the [questions](questions/README.md) banks — theory, coding,
   project deep-dive, system design, behavioral, and governance —
   each question answered with links into the corpus, not generic
   advice.
4. Practice the [take-homes](takehomes/README.md) — six formats, each
   mapped to projects you can already run.
5. Finish with the [system-design](questions/system-design.md) round
   — the hardest one, and the one this corpus trains best, because
   every design question reduces to evaluation and safety evidence.
